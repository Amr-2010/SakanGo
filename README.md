# SakanGo | سكن جو

**SakanGo 0.1.0 — independently runnable MVP**, with an Arabic-first responsive web application / PWA, REST API, PostgreSQL tenancy, broker and agency accounts, inquiry and appointment workflows, and optional mobile/Windows wrappers.

> This is a working MVP, **not** the full commercial platform shown in the design concept. Images and some local development listing data are illustrative. It does not include real AI, actual payments, signed Android/iOS installers, map search, 360-degree tours, or production certification.

## Scope implemented

- Responsive Arabic-first marketing homepage, listings search/filter by text, type, transaction, and budget.
- Property details, inquiries, appointment requests, user registration/login, favorites.
- Permission-aware dashboard for superadmin / agency administrator / broker showing scoped lead and booking counts.
- Property creation and listing management API; superadmin staff provisioning with distinct organizations.
- REST API with password hashing (scrypt), signed bearer tokens, RBAC and tenant boundaries for listing access, parameterized SQL, size and login-attempt limits.
- PostgreSQL schema auto-initialization when `DATABASE_URL` is configured. No browser-direct DB access.
- Render Blueprint (`render.yaml`) and Dockerfile.
- Installable PWA, Electron Windows shell, Capacitor Android/iOS scaffolding, and GitHub Actions build recipes (artifacts require a connected repo and builds).
- Rule-based property recommendation endpoint, clearly identified as **not generative AI**.

## Development startup (Node.js 20+)

```bash
# In the SakanGo folder
npm start
# Visit http://localhost:10000
npm test
```

Without `DATABASE_URL`, non-production mode uses a **temporary in-memory demo dataset**. It is reset after restarting the server and must not be used as a customer database. No external package is needed for local demo startup, although `npm install` is required for PostgreSQL and the desktop/mobile tooling.

To test dashboard in a disposable local session, set `ADMIN_EMAIL` and `ADMIN_PASSWORD` *before* starting the process (never commit credentials). Set a strong `JWT_SECRET` and use a PostgreSQL database for persistent data.

## Production on Render

1. Create a new **private** repository named `SakanGo` under your GitHub account, and push this directory as repository root.
2. In Render, navigate to the chosen project and select **New > Blueprint**; connect the new repository and review the proposed `sakango-web` web service and `sakango-db` PostgreSQL database.
3. Confirm service plan, pricing, region, and any `render.yaml` adjustments before approving the Blueprint. Keep SakanGo separate from any existing project/database.
4. Supply the required **manual** secrets `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and `ALLOWED_ORIGIN` to Render (set origin to the actual live `https://...onrender.com` domain). `JWT_SECRET` is generated by Blueprint, and `DATABASE_URL` is a reference to the new PostgreSQL instance.
5. Verify `https://<your-host>/api/health`, create the first listings while logged in as your admin, and perform browser + phone acceptance tests.

**Render free PostgreSQL may expire** and is not recommended for real customer information without a paid durable plan, backups, monitoring, and retention policy. Never reuse the Xerox Operation Manager database or secret values. When using an external TLS-enabled PostgreSQL with certificate validation, configure `PGSSLMODE=require` with a trusted certificate chain.

The provided Render connector might create services in a workspace but does not allow specifying an existing Render project ID. To ensure the intended project, deploy from the project's UI or move the newly created services into it in the Dashboard.

## API routes

| Method | Endpoint | Access |
|---|---|---|
| GET | `/api/health` | Public |
| POST | `/api/auth/register`, `/api/auth/login` | Public |
| GET | `/api/me` | Token optional |
| GET | `/api/listings`, `/api/listings/:id` | Public (published listings) |
| POST | `/api/listings` | Broker / agency admin / superadmin |
| PATCH | `/api/listings/:id` | Owner organization / superadmin |
| GET, POST | `/api/favorites` | Signed-in user |
| POST | `/api/leads`, `/api/appointments` | Public |
| GET | `/api/admin/summary` | Authorized business roles |
| POST | `/api/admin/staff` | Superadmin only |
| POST | `/api/assistant` | Public, rule-based demo |

## Desktop

`npm install && npm run desktop` launches a sandboxed Electron shell opening the deployed SakanGo site. Set `SAKANGO_URL=https://your-sakango-domain.onrender.com` to override the placeholder default URL. The `Build Windows EXE` GitHub Actions workflow can create an **unsigned** Windows installer on a Windows runner using `electron-builder`. Production code-signing is not included.

## Android / iOS

After `npm install`, change the deployed URL in `capacitor.config.json` to your actual HTTPS endpoint. Run `npm run mobile:android` for an Android Studio project, or `npm run mobile:ios` for an Xcode project on macOS. Android debug APK can be built with the GitHub Actions workflow. iOS app signing, Apple Developer account, store distribution, real native app functionality and push notifications have not been configured.
